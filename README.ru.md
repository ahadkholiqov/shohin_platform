# Shohin Platform

**Full-stack платформа продажи недвижимости и управления объектами**

[English](README.md) | **Русский**

Shohin Platform — веб-приложение для жилого комплекса, объединяющее публичный сайт недвижимости, каталог квартир, интерактивную шахматку и административную панель в единой системе.

Проект ориентирован на реальные бизнес-процессы продажи недвижимости, удобство использования на мобильных устройствах и понятную архитектуру.

Система предназначена для одного жилого комплекса, а не для работы в качестве мультиарендной SaaS-платформы.

## Возможности

### Публичный сайт

- **Главная страница жилого комплекса** — информация об объекте, ходе строительства, галерея и контакты.
- **Каталог квартир** — поиск по блоку, этажу, количеству комнат, цене и статусу доступности.
- **Интерактивная шахматка** — визуальное представление квартир по этажам и блокам здания.
- **Информация о квартирах** — площадь, стоимость, статус, описание и планировки.
- **Заявки покупателей** — отправка обращений по интересующим объектам.
- **Мобильный интерфейс** — удобная навигация и просмотр недвижимости со смартфонов.

### Административная панель

- Создание, редактирование и управление квартирами.
- Изменение статусов доступности.
- Просмотр и обработка заявок покупателей.
- Загрузка и управление изображениями галереи.
- Редактирование настроек и информационного содержимого сайта.
- Управление сведениями о ходе строительства.
- Изменение контактных данных и ссылок для связи.
- Защита административных API с помощью токена.

## Архитектура

Приложение состоит из двух основных компонентов.

**Frontend**

Клиентское приложение на React и TypeScript, реализующее публичный сайт недвижимости и интерфейс администратора.

Взаимодействие с сервером осуществляется через REST API.

**Backend**

Сервер ASP.NET Core отвечает за:

- Бизнес-логику.
- Работу с базой данных.
- Управление квартирами.
- Обработку заявок покупателей.
- Настройки сайта.
- Операции с галереей.
- Контроль административного доступа.
- Загрузку файлов.

**База данных**

PostgreSQL используется для хранения информации о квартирах, заявках, настройках сайта и других данных приложения.

Entity Framework Core обеспечивает доступ к данным и управление миграциями схемы.

При разработке Vite перенаправляет запросы `/api` и `/uploads` на ASP.NET Core.

После production-сборки frontend помещается в `plaza/wwwroot/`, откуда сервер может обслуживать его как статические файлы.

## Сборка и запуск

### 1. Требования

Для локального запуска необходимы:

- Git
- .NET 10 SDK
- Node.js и npm, совместимые с Vite 8
- PostgreSQL

Рекомендуется использовать Visual Studio Code или JetBrains Rider.

### 2. Клонирование репозитория

```bash
git clone https://github.com/ahadkholiqov/shohin_platform.git
cd shohin_platform
```

Если не указано иное, следующие команды выполняются из корня репозитория.

### 3. Настройка PostgreSQL

Создайте локальную базу PostgreSQL с названием `shohin`.

В корневой папке репозитория, рядом с `frontend/` и `plaza/`, создайте файл `.env`.

Пример:

```dotenv
DATABASE_URL=postgresql://postgres:YOUR_PASSWORD@localhost:5432/shohin
ADMIN_TOKEN=REPLACE_WITH_A_LONG_RANDOM_SECRET
```

Замените примерные значения на настоящие параметры PostgreSQL и надёжный случайно сгенерированный токен администратора.

Если пароль содержит специальные символы, при необходимости закодируйте их для использования в URL.

**Не добавляйте `.env` и настоящие секреты в Git.**

Backend загружает этот файл из родительского каталога папки `plaza/`.

### 4. Запуск backend

Откройте терминал в корне репозитория:

```bash
cd plaza
dotnet restore
dotnet run --launch-profile http
```

Адрес сервера:

`http://localhost:5241`

Миграции EF Core автоматически применяются во время запуска приложения.

PostgreSQL должен быть запущен, а база данных должна существовать и быть доступной.

### 5. Запуск frontend

Откройте второй терминал в корне репозитория:

```bash
cd frontend
npm ci
npm run dev
```

Обычно frontend доступен по адресу:

`http://localhost:5173`

Vite перенаправляет запросы API и загрузки файлов на ASP.NET Core.

### 6. Демонстрационные данные (необязательно)

В пустую базу можно добавить тестовые квартиры и настройки сайта через защищённый административный endpoint.

Пример с использованием cURL:

```bash
curl -X POST http://localhost:5241/api/admin/seed -H "X-Admin-Token: YOUR_ADMIN_TOKEN"
```

Замените `YOUR_ADMIN_TOKEN` на токен из `.env`.

В Windows PowerShell рекомендуется использовать `curl.exe` вместо псевдонима `curl`.

**Демонстрационные данные предназначены только для локального тестирования.** Сведения о квартирах, их статусах и ходе строительства не являются подтверждёнными реальными предложениями.

### 7. Проверка работы

Откройте следующие страницы frontend:

| Путь | Что проверить |
|---|---|
| `/` | Главная страница жилого комплекса |
| `/catalog` | Каталог квартир и фильтрация |
| `/chessboard` | Интерактивная шахматка |
| `/admin/login` | Авторизация администратора |

Обычно используется адрес `http://localhost:5173`.

Публичный API также доступен по адресу:

`http://localhost:5241/api/apartments`

При корректном запуске backend должен возвращать JSON.

Если квартир в базе ещё нет, допустим пустой массив.

### 8. Сборка и проверка

Из папки `frontend/`:

```bash
npm ci
npm run lint
npm run build
```

Из папки `plaza/`:

```bash
dotnet build
```

Сборка frontend включает проверку TypeScript и Vite.

Результат сборки сохраняется в `plaza/wwwroot/`.

Эти команды проверяют компиляцию и статические правила, но не заменяют полноценное end-to-end тестирование.
